# `internal Firebird consistency check (decompression overran buffer (179))`

Полностью сообщение обычно выглядит так: `internal Firebird consistency check (decompression overran buffer (179), file: sqz.cpp line: ...)`. Оно появляется в запросе, в `gbak` или в `gfix -v`.

## Что это значит

Firebird хранит каждую запись в сжатом виде: простое кодирование повторов. Если при распаковке результат не помещается в формат записи, значит, сохранённые байты повреждены. Причины — сбойный диск, неудачное копирование, падение посреди записи на диск или страница, затёртая чужими данными. Движок прерывает оператор, который дошёл до этой записи, поэтому `SELECT` или бэкап этой таблицы каждый раз падает на одном и том же месте. Остальные записи таблицы обычно целы.

{% include steps-ru.md %}

`gfix -mend` — штатный ответ движка именно на эту ошибку: он помечает повреждённую запись, и следующий бэкап её пропускает.

{% include fbrescue-ru.md %}

При этой ошибке fbrescue читает все записи таблицы и выгружает остальные. Записи, которые не распаковываются, попадают в `_errors.jsonl` со страницей и строкой. Запись, которая продолжается на другой странице (такое бывает с записями больше страницы), теряется, только если повреждён один из её кусков.
