# `database file appears corrupt` / `page ... is of wrong type`

Обычно они идут вместе: `database file appears corrupt (...)`, затем `wrong page type` и `page 1234 is of wrong type (expected 5, found 0)`.

## Что это значит

База Firebird — это файл из страниц одного размера. В первом байте каждой страницы записан её тип: данные, индекс, pointer, blob, таблица транзакций и так далее. Движок перешёл по ссылке на страницу 1234, ожидая один тип, а нашёл другой. *found 0* значит, что страница обнулена. Так бывает после падения сервера, сбоя диска, починки файловой системы или неудачного копирования. Другое число обычно значит, что на странице лежит содержимое другой страницы.

Что потеряно, зависит от того, какая это страница:

| Тип страницы (ожидался) | Что потеряно |
|---|---|
| 5, данные | строки на этой странице |
| 4, pointer | для движка — перечисленные там страницы данных таблицы; сами страницы целы |
| 7, индекс | ничего: индексы строятся заново из данных |
| 8, blob | значения BLOB на этой странице |
| 3, таблица транзакций | см. [`cannot find tip page`](../cannot-find-tip-page/) |

`fbrescue scan` покажет все страницы, которые не такие, какими должны быть, а по каждой таблице — сколько страниц данных и записей до неё доступно. При выгрузке:

- страницы данных, которых уже нет в pointer-страницах таблицы, находятся чтением всего файла: каждая страница данных хранит номер своей таблицы и своё место в ней;
- страница, найденная на месте другой, читается оттуда: Firebird 3 и новее хранит номер страницы на самой странице;
- повреждённые индексные страницы не мешают: выгрузка читает только данные.
