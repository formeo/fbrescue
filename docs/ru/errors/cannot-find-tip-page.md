# `internal Firebird consistency check (cannot find tip page (165))`

## Что это значит

На страницах TIP (transaction inventory) по два бита на транзакцию записано её состояние: подтверждена, отменена или ещё активна. Каждая версия строки хранит номер транзакции, которая её записала, и по этому номеру движок решает, какую версию видит запрос. Если страница TIP пропала, обнулена или затёрта, решить он не может и отказывается работать. Часто база вообще не открывается, и `gbak` не запускается.

Сами данные при этом обычно не тронуты: потерян только учёт транзакций.

При этой ошибке fbrescue всё равно выгружает все таблицы. Транзакции старше OIT (oldest interesting transaction из заголовка) по определению подтверждены. Для более новых транзакций, чьё состояние потеряно, fbrescue берёт самую новую версию строки. Для подтверждённых транзакций, а это почти все, это правильная версия. Выгрузка сообщает, для скольких строк пришлось так решать: среди них могут оказаться и отменённые изменения. Если страницы TIP просто лежат не на своём месте, fbrescue находит их сканированием файла.
